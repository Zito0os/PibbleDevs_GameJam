## 1. VISIÓN GENERAL DEL JUEGO
## ══════════════════════════════════════════════════════════

Castle of Self es un juego de exploración competitiva para 2 jugadores en tiempo real
ambientado en un castillo mágico. La narrativa: un personaje con baja autoestima
encuentra un papel con un número de teléfono. Al llamarlo, aparece un mago que lo
teletransporta a su castillo junto con un CLON de sí mismo. El mago les dice que si el
jugador derrota a su clon (escapa del castillo primero), eliminará todos sus defectos.

OBJETIVO DEL JUEGO:
Ser el primero en encontrar y abrir exitosamente la puerta dorada CORRECTA del castillo.
Hay varias puertas doradas, pero solo UNA es la salida real (determinada aleatoriamente
al inicio de la partida). Abrir la puerta incorrecta rompe la llave dorada.

PLATAFORMA: PC
CONTROLES: Teclado + Mouse para el jugador humano. El clon es controlado por IA.
LENGUAJE: C# en Unity 2022 LTS
REPOSITORIO: GitHub con ramas por miembro del equipo

## 2. MECÁNICAS COMPLETAS DEL JUEGO
## ══════════════════════════════════════════════════════════

### 2.1 MOVIMIENTO
- WASD para moverse por el castillo
- Shift para correr más rápido (consume stamina)
- Si la stamina llega a 0, el jugador camina más lento hasta que se recargue parcialmente
- La stamina se recarga automáticamente cuando no se corre
- Los hechizos enemigos pueden modificar la velocidad del jugador (slow, freeze)

### 2.2 ITEMS — SISTEMA COMPLETO

Todos los items se obtienen abriendo cofres. Los cofres están distribuidos por los
cuartos del castillo. Al abrir un cofre, aparece un item aleatorio del pool global.

TIPOS DE ITEM:

  [A] LLAVE PLATEADA
      - Sirve para abrir PUERTAS PLATEADAS
      - Las puertas plateadas permiten avanzar a nuevas zonas del castillo
      - Para usarla: acercarse a puerta plateada + tener llave en inventario + pasar el skill check
      - Si el skill check FALLA: la llave desaparece del inventario y reaparece en cofre random

  [B] LLAVE DORADA
      - Sirve para intentar abrir PUERTAS DORADAS
      - Solo UNA puerta dorada es la ganadora (flag isWinDoor asignado por GameManager al inicio)
      - Si se abre la puerta CORRECTA: el jugador GANA la partida
      - Si se abre una puerta INCORRECTA: la llave se rompe y reaparece en cofre random
      - Cuando un jugador TIENE una llave dorada: aparece alerta en minimapa del rival

  [C] HECHIZO DE RALENTIZACIÓN (Slow)
      - Se lanza con Q apuntando con el mouse
      - Si impacta al rival: reduce su velocidad de movimiento un 30% durante N segundos
      - Rareza: común

  [D] HECHIZO DE CONGELACIÓN (Freeze)
      - Se lanza con Q apuntando con el mouse
      - Si impacta al rival: paraliza COMPLETAMENTE su movimiento durante 3 segundos
      - Rareza: poco común

  [E] HECHIZO DE ELIMINAR ITEMS (ClearInventory)
      - Se lanza con Q apuntando con el mouse
      - Si impacta al rival: VACÍA TODO su inventario (llaves + hechizos)
      - Todos los items vaciados reaparecen en cofres aleatorios del mapa
      - Rareza: raro (el más difícil de encontrar)

  [F] HECHIZO DE ROBAR LLAVE (StealKey)
      - Se lanza con Q apuntando con el mouse
      - Si impacta al rival: extrae UNA llave aleatoria de su inventario
      - La llave robada reaparece en un cofre aleatorio del mapa
      - Rareza: poco común

### 2.3 MECÁNICA DE SKILL CHECK (ruleta)

Cuando el jugador intenta abrir una puerta (plateada o dorada) con la llave correcta:
  1. Aparece un overlay en pantalla: un círculo con una flecha rotatoria tipo "ruleta"
  2. En el círculo hay una pequeña zona de color verde (tamaño y posición aleatorios)
  3. El jugador debe hacer clic cuando la flecha apunta a la zona verde
  4. Si acierta: la acción de la puerta se ejecuta (abrir / ganar)
  5. Si falla: la llave desaparece del inventario y reaparece en cofre random

### 2.4 COFRES Y RESPAWN DE ITEMS

- Los cofres están distribuidos en los cuartos del castillo (posición fija, definida por Prog A)
- Al abrir un cofre, este entra en un estado de "vacío" con cooldown
- Cuando un item es destruido/perdido, el ItemSpawner lo reasigna a un cofre aleatorio disponible
- El cofre que recibe el item vuelve a estar disponible para ser abierto

### 2.5 MINIMAPA Y ALERTA DE LLAVE DORADA

- El minimapa muestra posición de ambos jugadores en tiempo real
- Cuando el RIVAL porta una llave dorada:
  - Aparece un ícono especial sobre su punto en el minimapa
  - Aparece un texto de alerta en el HUD del jugador local ("¡El rival tiene una llave dorada!")
- Cuando el rival pierde la llave dorada: las alertas desaparecen

### 2.6 CONDICIÓN DE VICTORIA Y DERROTA

- VICTORIA: el jugador abre la puerta dorada correcta con skill check exitoso
- DERROTA: el clon rival abre la puerta dorada correcta antes que el jugador
- Al detectarse la victoria/derrota: GameManager carga la escena Result

## 4. SISTEMA DE EVENTOS — EventManager.cs
## ══════════════════════════════════════════════════════════

EventManager.cs es creado y mantenido por Prog A. Es un singleton estático con eventos
System.Action. NADIE modifica EventManager.cs excepto Prog A.
Prog B solo se suscribe y dispara eventos desde sus propios scripts.

DECLARACIÓN COMPLETA DEL EVENTMANAGER:

  public static class EventManager
  {
      // ── Juego ──────────────────────────────────────────────
      public static Action OnGameStarted;
      public static Action<PlayerController> OnGameWon;
      public static Action OnGameOver;

      // ── Puertas ────────────────────────────────────────────
      public static Action<DoorController> OnDoorUnlocked;
      public static Action OnSkillCheckPassed;
      public static Action OnSkillCheckFailed;
      public static Action<PlayerController> OnWrongGoldDoor;

      // ── Items y cofres ─────────────────────────────────────
      public static Action<ItemData, Vector3> OnChestOpened;
      public static Action<ItemData, ChestController> OnItemRespawned;
      public static Action<PlayerController> OnInventoryChanged;

      // ── Stamina ────────────────────────────────────────────
      public static Action<float> OnStaminaChanged;   // valor: 0.0f a 1.0f

      // ── Hechizos ───────────────────────────────────────────
      public static Action<SpellItem, PlayerController> OnSpellCast;
      public static Action<SpellItem, PlayerController> OnSpellHit;

      // ── Llave dorada (Prog B dispara, Prog A escucha en minimapa) ──
      public static Action<PlayerController> OnGoldenKeyPickedUp;
      public static Action<PlayerController> OnGoldenKeyLost;

      // ── Interacción ────────────────────────────────────────
      public static Action<IInteractable> OnPlayerInteract;
  }

PATRÓN DE SUSCRIPCIÓN CORRECTO (siempre desuscribirse en OnDisable):

  void OnEnable()
  {
      EventManager.OnInventoryChanged += RefreshUI;
      EventManager.OnSkillCheckFailed += HandleKeyLost;
  }

  void OnDisable()
  {
      EventManager.OnInventoryChanged -= RefreshUI;
      EventManager.OnSkillCheckFailed -= HandleKeyLost;
  }

PATRÓN DE DISPARO DE EVENTO:

  EventManager.OnInventoryChanged?.Invoke(playerController);

  // Item.cs — ScriptableObject base
  public abstract class Item : ScriptableObject
  {
      public string itemName;
      public Sprite icon;
      public ItemType type;  // enum: Key, Spell
  }

  // KeyItem.cs — hereda de Item
  public class KeyItem : Item
  {
      public KeyType keyType;  // enum: Silver, Gold
  }

  // SpellItem.cs — hereda de Item
  public class SpellItem : Item
  {
      public SpellType spellType;   // enum: Slow, Freeze, ClearInventory, StealKey
      public float duration;        // duración del efecto en segundos
      public float slowAmount;      // solo para Slow (ej: 0.3f = 30% de reducción)
  }

  // ItemPool.cs — ScriptableObject con lista global de items y pesos de probabilidad
  public class ItemPool : ScriptableObject
  {
      public List<ItemEntry> entries;

      [System.Serializable]
      public class ItemEntry
      {
          public Item item;
          public float weight;  // peso de probabilidad (ej: llave plateada = 10, hechizo clear = 1)
      }
  }

ENUMS DEL PROYECTO (definidos por Prog A, usados por todos):

    - Controla la ruleta del overlay
    - Al activarse: genera zona verde random (tamaño y ángulo)
    - Rota la flecha a velocidad constante
    - Al clic del jugador: comprueba si la flecha está en zona verde
        Éxito: OnSkillCheckPassed?.Invoke()
        Fallo: OnSkillCheckFailed?.Invoke()
    - Se desactiva después del resultado

  MinimapController.cs
    - Actualiza posición de iconos de jugadores en el minimapa cada frame
    - Suscrito a OnGoldenKeyPickedUp(player): muestra ícono de alerta sobre el rival
    - Suscrito a OnGoldenKeyLost(player): oculta el ícono de alerta

  CloneAI.cs
    - Adjunto al Clone.prefab (encima de PlayerController)
    - Pathfinding simple: explora cuartos, busca cofres, recoge items
    - Si tiene llave: busca la puerta correspondiente e intenta abrirla

  AudioManager.cs

  MainMenuManager.cs

  CinematicController.cs
    - Reproduce Timeline o Animator de la intro

    - Al terminar: dispara OnCinematicEnd (local) → activa menú principal

### 7B — SCRIPTS DE PROG B (Player & Items) ← ROL ACTIVO
Estos son los scripts que el usuario (Programador B) debe desarrollar.

  PlayerController.cs
    Namespace: CastleOfSelf.Player
    Responsabilidad: movimiento del jugador, integración con stamina, flag de input
    Variables clave:
      [SerializeField] float moveSpeed = 4f;
      [SerializeField] float sprintMultiplier = 1.8f;
      bool inputEnabled = true;      // FreezeEffect lo pone en false
      bool isSprinting = false;
      Rigidbody rb;
      StaminaSystem staminaSystem;
    Métodos:
      void Update():
        if (!inputEnabled) return;
        Leer Input.GetAxisRaw("Horizontal") y "Vertical"
        Detectar Input.GetKey(KeyCode.LeftShift) && staminaSystem.HasStamina()
        Aplicar velocidad: rb.linearVelocity = direction * moveSpeed * (isSprinting ? sprintMultiplier : 1f)
      void SetInputEnabled(bool value): usado por FreezeEffect
      void ApplySpeedModifier(float multiplier, float duration): usado por SlowEffect (Coroutine)

  StaminaSystem.cs
    Namespace: CastleOfSelf.Player
    Responsabilidad: gestionar la barra de stamina
    Variables clave:
      [SerializeField] float maxStamina = 100f;
      [SerializeField] float drainRate = 20f;     // por segundo corriendo
      [SerializeField] float rechargeRate = 15f;  // por segundo en reposo
      [SerializeField] float exhaustedThreshold = 20f; // stamina mínima para volver a correr
      float currentStamina;
      bool isExhausted;
    Métodos:
      bool HasStamina(): retorna currentStamina > 0 && !isExhausted
      void Drain(): currentStamina -= drainRate * Time.deltaTime; verificar exhaustion
      void Recharge(): currentStamina += rechargeRate * Time.deltaTime
      Al cambiar currentStamina: EventManager.OnStaminaChanged?.Invoke(currentStamina / maxStamina)

  PlayerInteraction.cs
    Namespace: CastleOfSelf.Player
    Responsabilidad: detectar IInteractable en rango y activar con tecla E
    Variables clave:
      IInteractable currentInteractable;
      PlayerController playerController;
    Lógica:
      OnTriggerEnter: si el objeto tiene IInteractable, guardarlo en currentInteractable
      OnTriggerExit: limpiar currentInteractable
      Update(): si Input.GetKeyDown(KeyCode.E) && currentInteractable != null:
        currentInteractable.Interact(playerController)
        EventManager.OnPlayerInteract?.Invoke(currentInteractable)

    public interface IInteractable

    }

  Inventory.cs
    Namespace: CastleOfSelf.Items
    Responsabilidad: lista de items del jugador
    Variables clave:
      [SerializeField] int maxSlots = 6;
      List<Item> items = new List<Item>();
      PlayerController owner;
      ItemSpawner itemSpawner;  // referencia, asignada por GameManager o Inspector
    Métodos:
      bool AddItem(Item item):
        Si items.Count >= maxSlots: retornar false
        items.Add(item)
        Si item es KeyItem con keyType == Gold: OnGoldenKeyPickedUp?.Invoke(owner)
        OnInventoryChanged?.Invoke(owner)
        retornar true
      void RemoveItem(Item item):
        items.Remove(item)
        Si item era KeyItem Gold: OnGoldenKeyLost?.Invoke(owner)
        OnInventoryChanged?.Invoke(owner)
      void ClearAll():
        Por cada item en items: itemSpawner.RespawnItem(item)
        items.Clear()
        OnInventoryChanged?.Invoke(owner)
      bool HasKey(KeyType type): retorna items.OfType<KeyItem>().Any(k => k.keyType == type)
      KeyItem GetRandomKey(): retorna items.OfType<KeyItem>().OrderBy(_ => Random.value).FirstOrDefault()
      List<Item> GetAllItems(): retorna copia de la lista

  ChestController.cs
    Namespace: CastleOfSelf.Items
    Responsabilidad: lógica del cofre al ser abierto
    Implementa: IInteractable
    Variables clave:
      bool isOpen = false;
      bool hasItem = false;
      Item storedItem = null;
      [SerializeField] float reopenCooldown = 5f;
      Animator animator;
      ItemSpawner itemSpawner;
    Métodos:
      void Interact(PlayerController player):
        Si isOpen || !hasItem: return
        isOpen = true
        animator.SetTrigger("Open")
        player.GetComponent<Inventory>().AddItem(storedItem)
        EventManager.OnChestOpened?.Invoke(storedItem, transform.position)
        storedItem = null
        hasItem = false
        StartCoroutine(ReopenCooldown())
      IEnumerator ReopenCooldown():
        yield return new WaitForSeconds(reopenCooldown)
        isOpen = false
        animator.SetTrigger("Close")
      void ReceiveItem(Item item):
        storedItem = item
        hasItem = true
        // Activar efecto visual de "cofre listo"

  ItemSpawner.cs
    Namespace: CastleOfSelf.Items
    Responsabilidad: pool global de items, reasignar items a cofres aleatorios
    Variables clave:
      [SerializeField] ItemPool itemPool;
      List<ChestController> allChests;   // llenada por CastleGenerator (Prog A)
    Métodos (llamados por CastleGenerator de Prog A para inicializar):
      void RegisterChest(ChestController chest): allChests.Add(chest)
    Métodos de uso:
      Item GetRandomItem():
        Usa los pesos del ItemPool para elegir item aleatoriamente (método de ruleta)
        Retorna una instancia (ScriptableObject.Instantiate o referencia directa)
      void RespawnItem(Item item):
        StartCoroutine(RespawnCoroutine(item))
      IEnumerator RespawnCoroutine(Item item):
        yield return new WaitForSeconds(0.5f)  // pequeño delay
        ChestController target = allChests
          .Where(c => !c.hasItem && !c.isOpen)
          .OrderBy(_ => Random.value)
          .FirstOrDefault()
        Si target != null:
          target.ReceiveItem(item)
          EventManager.OnItemRespawned?.Invoke(item, target)
    Suscripciones en OnEnable:
      EventManager.OnSkillCheckFailed += () => { /* la llave ya fue removida del inventario por DoorController antes de este evento */ }
      EventManager.OnWrongGoldDoor += (player) => { /* igual, DoorController ya removió la llave */ }
    NOTA: ItemSpawner no necesita suscribirse a OnSkillCheckFailed para hacer respawn.
    DoorController (Prog A) llama a player.GetComponent<Inventory>().RemoveItem(key)
    antes de disparar el evento, y Inventory.RemoveItem internamente llama RespawnItem.

  SpellLauncher.cs
    Namespace: CastleOfSelf.Player
    Responsabilidad: instanciar proyectil de hechizo en dirección del mouse
    Variables clave:
      [SerializeField] GameObject spellProjectilePrefab;
      Inventory inventory;
      PlayerController playerController;
    Métodos:
      void Update():
        Si Input.GetKeyDown(KeyCode.Q):
          SpellItem spell = inventory.GetAllItems().OfType<SpellItem>().FirstOrDefault()
          Si spell == null: return
          inventory.RemoveItem(spell)
          Vector3 mousePos = Camera.main.ScreenToWorldPoint(Input.mousePosition)
          mousePos.z = transform.position.z
          Vector3 direction = (mousePos - transform.position).normalized
          GameObject proj = Instantiate(spellProjectilePrefab, transform.position, Quaternion.identity)
          SpellProjectile sp = proj.GetComponent<SpellProjectile>()
          sp.Initialize(spell, direction, playerController)
          EventManager.OnSpellCast?.Invoke(spell, playerController)

  SpellProjectile.cs
    Namespace: CastleOfSelf.Player
    Responsabilidad: mover el proyectil y detectar impacto con el rival
    Variables clave:

      [SerializeField] float lifetime = 4f;
      SpellItem spellData;
      Vector3 direction;
      PlayerController owner;
    Métodos:
      void Initialize(SpellItem spell, Vector3 dir, PlayerController ownerPlayer):
        spellData = spell; direction = dir; owner = ownerPlayer
        Destroy(gameObject, lifetime)
      void Update(): transform.position += direction * speed * Time.deltaTime
      void OnTriggerEnter(Collider other):
        PlayerController target = other.GetComponent<PlayerController>()

  SlowEffect.cs
    Namespace: CastleOfSelf.Items
    Responsabilidad: aplicar reducción de velocidad al objetivo
    Suscrito a: EventManager.OnSpellHit
    Lógica:
      void HandleSpellHit(SpellItem spell, PlayerController target):
        Si spell.spellType != SpellType.Slow: return
        StartCoroutine(ApplySlow(spell, target))
      IEnumerator ApplySlow(SpellItem spell, PlayerController target):
        float original = target.moveSpeed
        target.moveSpeed *= (1f - spell.slowAmount)
        yield return new WaitForSeconds(spell.duration)
        target.moveSpeed = original

  FreezeEffect.cs
    Namespace: CastleOfSelf.Items
    Responsabilidad: paralizar completamente al objetivo
    Suscrito a: EventManager.OnSpellHit
    Lógica:
      void HandleSpellHit(SpellItem spell, PlayerController target):

      IEnumerator ApplyFreeze(SpellItem spell, PlayerController target):
        target.SetInputEnabled(false)
        target.rb.linearVelocity = Vector3.zero
        yield return new WaitForSeconds(spell.duration)  // 3f
        target.SetInputEnabled(true)

## 10. CONVENCIONES DE CÓDIGO DEL PROYECTO
## ══════════════════════════════════════════════════════════

- Namespaces: CastleOfSelf (raíz), CastleOfSelf.Player, CastleOfSelf.Items, CastleOfSelf.UI
- Siempre desuscribirse de eventos en OnDisable() para evitar memory leaks
- Coroutines para efectos temporales (slow, freeze): IEnumerator + StartCoroutine
- Singletons: patrón con Instance estático privado, Awake() asigna la instancia
- [SerializeField] para referencias asignadas en el Inspector (no public)
- NUNCA usar GameObject.Find() en Update() — usar referencias directas o eventos
- NUNCA usar FindObjectOfType() en Update() — solo en Awake() o Start()
- Comentarios en español para consistencia del equipo
- Nombres de métodos y variables en inglés (convención de Unity)
- Un archivo por clase, nombre del archivo igual al nombre de la clase
- Estructura de un MonoBehaviour: Variables → Lifecycle (Awake, Start, OnEnable,
  OnDisable, Update) → Métodos públicos → Métodos privados → Coroutines
